The redesign is a presentation-layer refactor. All math (cockpit, profitLock, profitCashPlan, scenarioPlanner, sellFills, robinhoodCsv, tradeJournal, researchProvider, marketData) lives in src/lib/ with passing tests — none of that needs to change.

The current src/App.tsx is 5,042 lines and src/App.css is 1,883 lines. Both are mostly layout. The plan extracts a Claude-Code-style shell, splits the monolith into per-view files, replaces ad-hoc panels with a small set of primitives, and migrates existing state hooks unchanged.

Guiding rules. 1) Don't touch src/lib/* or its tests. 2) Each phase ends with green lint / typecheck / test / build. 3) Keep PRs ≤ 500 changed lines per the workflow standard — split phases across multiple PRs when needed. 4) Old App.css stays in place until its panels are visually replaced; delete in P10.

— design tokens (locked) match prototype 1:1

Tokens come straight from docs/prototypes/redesign.html. They go into src/styles/tokens.css as CSS custom properties on :root and [data-theme="light"]. No CSS-in-JS, no Tailwind — match the Claude Code feel: single stylesheet, monospace numbers, dashed dividers.

— cross-cutting concerns apply throughout
·
Workflow + safety rails
Per the agent-workflow standard.
always-on
rules
  • One issue → one worktree → one branch → one PR.
  • Keep PRs ≤ 500 changed lines (P2 splits into 3 PRs by design).
  • Fresh main + green CI before merge.
  • Risk-tiered review: P2 / P8 require a self-review pass before merge.
  • Reset session between unrelated phases.
checks per phase
  • npm run lint
  • npm run typecheck
  • npm test
  • npm run build
non-goals
  • No new business logic in src/lib/.
  • No router migration (single-page useState view switch is enough).
  • No Tailwind, no CSS-in-JS, no design system import.
  • No broker integrations, no live order placement, no remote sync.
decision log
  • Theme: CSS variables on :root + data-theme.
  • Fonts: @fontsource-variable for offline.
  • State: per-domain hooks in src/state/; no Zustand.
  • Hotkeys: small useHotkeys + chord buffer, no react-hotkeys dep.
Open this side-by-side with the prototype. Cross-reference docs/prototypes/redesign.html as the visual contract for every phase from P3 onward. Pixel diffs against that file are the cheapest acceptance test you have.
