# AGE-546 Handoff

## Status

Implemented the Codex research queue and import workflow on branch
`dylanmccavitt2015/age-546-0707-codex-research-queue-and-import-workflow`.

The research card now has a local Codex queue panel. `Queue Codex request`
creates a structured request JSON download for the selected symbol with symbol,
company name, AI-stack layer, current editable card fields, output schema,
guardrails, worker prompt path, and expected ignored result path. `Check result`
surfaces a missing-result state when no local result has been imported.
`Import result JSON` validates a local result file before drafting thesis,
catalyst, invalidation, risk notes, review date, source notes, and source
metadata into the existing editable research card as AI-drafted / Needs review.

Generated request/result JSON is ignored under `research-queue/requests/*.json`
and `research-queue/results/*.json`; committed `.gitkeep`, schemas, queue README,
and worker docs preserve the local queue shape. No OpenAI API calls, API keys,
brokerage access, order execution, or automated trading were added.

## Next

Review the PR, then merge and fast-forward canonical `main`. After merge, move
AGE-546 to `Done`.

## Risks

- The app can download a request file and import a selected result file, but it
  does not directly write into `research-queue/` because the browser cannot
  silently write local files. The UI displays the intended ignored request and
  result paths.
- A human/Codex worker still has to process pending request JSON manually with
  browser, Chrome, ChatGPT, or Deep Research and write valid result JSON.
- Browser verification covered queue and missing-result states. Result import
  validation and AI-drafted field mapping are covered by unit tests.
