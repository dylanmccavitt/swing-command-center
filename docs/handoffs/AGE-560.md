## Status

Implemented AGE-560 on branch

PR #13 / AGE-532 was merged first at

AGE-560 was moved from Blocked to In Progress after the start gate was cleared.

This slice adds a typed, versioned local persistence boundary and wires it into
the React app. User-entered holdings/lots, edited research cards, selected
symbols, research filters, scenario planner forms, portfolio/settings inputs,
pay-yourself inputs, journal rows, manual sell fills, Robinhood import batches,
Robinhood normalized rows and review decisions, and buying-power inputs now
persist in browser-local storage across reloads.

Invalid JSON, unsupported schema versions, and malformed core arrays fail
visibly without hydrating over current seed/default app state. Missing optional
UI fields hydrate from defaults with warnings. The settings panel now includes a
visible reset action that clears local saved state and reloads seed defaults.

## Verified

- Manual AAPL shares / average cost saved to local browser storage and hydrated
  after reload.
- Cash goal settings saved and hydrated after reload.
- Reset local data restored seed/default local state and remained reset after
  another reload.
- Robinhood import review states are preserved through snapshot hydration in
  tests, and only accepted imported sell rows map into buying-power records.
- Invalid stored data and unsupported schema versions are rejected without a
  successful hydration result.
- Desktop `1440x1200` and mobile `390x900` had zero horizontal document
  overflow, with the local-state reset UI visible.

## Risks

- `localStorage` is browser-local only. It does not provide cross-device sync,
  backup, or account recovery.
- Unsupported future schema versions intentionally block hydration until reset
  or a migration is added.
- The app still has no broker login, scraping, credential handling, order
  execution, automated trading, or tax-advice behavior.
